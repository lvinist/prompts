## Key Design Decisions

1. **Benchmark**: Snapshot excludes lat/lon/crs-derived fields (9 ENTRY fields only). On restore, `_syncControllers` dispatches `FormCrsChanged` (re-sets CRS) + `FormLatLonComputed` (re-triggers `_computeLatLon` via the 55.4 projection path). A snapshot with out-of-bounds northing (99,999,999) restores cleanly and then fails projection exactly as fresh input — proven by unit test `projection-revalidation` case. Encode guards against null northing/easting by returning null (never serializes sentinel coordinates into JSON that would trigger the `kBenchmarkProjectionFailureMessage` path).

2. **Inventory**: `_onRestoreRequested` in `InventoryBloc` calls `repository.getInventoryItemById(event.id)` to reload the CONTEXT item from the repository, then applies ENTRY snapshot fields (`zoneId`, `itemCode`, `description`, `quantity`) on top. CONTEXT fields (`id`, `createdAt`, `updatedAt`) are never snapshotted — proven by unit test. The `siteId` parameter flows from parent `InventoryItemEntryScreen` → `_InventoryItemFormView` → `decode()` for site-scoping verification.

3. **Data-bucket (Q2 Option A)**: Snapshot contains only `zoneId`, `acquisitionDate`, `notes` (+ `siteId` for validation). File bytes are never serialized. On restore, `_applyRestore` uses `addPostFrameCallback` to set `_selectedZoneId`, `_acquisitionDate`, `_notesController.text`, then re-encodes the snapshot. The `_metadataRestored` flag (decoupled from the transient restore lifecycle) gates the `_showRePickBanner` getter, which renders the `"File tidak tersedia — pilih ulang."` banner (Indonesian l10n: `dataBucketFileUnavailable`). The file picker section shows the `"Pilih File"` placeholder. The snapshot is cleared on close (`_handleClose`) and on explicit discard.

4. **Version-gating**: All three `decode()` methods return `null` on version mismatch (version field checked against a `kCurrentVersion` constant), malformed JSON, missing required fields, or siteId mismatch. This prevents stale snapshots from surfacing broken data.
